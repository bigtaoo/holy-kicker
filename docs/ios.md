# iOS release plan

Status, 2026-10-09: steps 1–3 (the shell, Game Center's nickname, AdMob) work on a phone from
TestFlight; step 4 (the ad-free card) is built and waits for a sandbox purchase; step 5 is a plan.

The iOS app is the web build inside a Capacitor shell (WKWebView), like the other hosts it is
one more `Platform` (`client/src/platform/types.ts`). Most of the native plumbing already
works in the sibling project **`D:\funny`** (shipped to TestFlight and through App Review):
read `D:\funny\design\game\IOS_RELEASE.md` before touching the native side. This document
says what we take from funny, what we build new, and in which order.

## Scope of the first release

| In | Out (later, see the last section) |
|---|---|
| The whole game, iPhone, portrait | iPad layout (runs in iPhone compatibility mode) |
| Game Center sign-in, silent where possible: the player's nickname on the boards | Cloud save, Game Center leaderboards / achievements |
| AdMob: rewarded + interstitial, Google's consent form (UMP) in the EEA/UK | Banner, ATT / personalised ads |
| One purchase: the **ad-free card** (non-consumable), with Restore | Jade packs, starter pack, battle pass |
| Every storefront except mainland China | China (needs a game licence for IAP) |
| Builds and uploads from GitHub Actions (no Mac needed) | OTA web-bundle updates |

Why only the ad-free card: an active player earns about 100 jade a day and jade has few sinks
(the jade chest, quick patrols, two monks), so jade packs would sell poorly; jade in a local
save is lost on reinstall, so selling it needs a server account and cloud save first; and
jade buys the jade chest's next-chapter gear, which is pay-to-win. The card only removes
waiting; every daily cap stays, so balance never has to price in a paying player.

## Architecture

```
client/
  capacitor.config.ts        appId, webDir 'dist-ios', ios.contentInset 'never'
  vite.ios.config.js         build:ios → client/dist-ios/ (in npm run check)
  src/main.ios.ts            entry, through boot.ts
  src/platform/ios/
    IosPlatform.ts           extends WebPlatform: storage, openUrl, languages, device, keyboard
    bridge.ts                typed access to window.HKNative, feature-detected
    gameCenter.ts            (step 2) the nickname and the sign-in offer (tested)
    admob.ts                 (step 3) Ads and AdPrivacy over the shell's AdMob (tested)
    mirrorStore.ts           localStorage + the UserDefaults copy (tested)
    shell.test.ts            pins the native project to the web side as text
    storeKit.ts              (step 4) the ad-free card's Store over the shell's StoreKit (tested)
    adFree.ts                (step 4) the Ads decorator used once the card is owned (tested)
  ios/App/                   the native project, committed; generated by
                             `npx cap add ios --packagemanager CocoaPods`
    Podfile                  pods signed with the app (CODE_SIGNING_ALLOWED NO), iOS 15
    App/AppDelegate.swift    stock, plus the .ambient audio session
    App/SceneDelegate.swift  stock, roots the window in HKBridgeViewController
    App/HKBridgeViewController.swift   the bridge, bottom-edge gestures
    App/KeyStore.swift       the UserDefaults copy of the key store
    App/GameCenter.swift     (step 2) GameKit's sign-in, the alias, the kept sheet
    App/AdMob.swift          (step 3) UMP consent, a rewarded and an interstitial kept loaded
    App/Store.swift          (step 4) StoreKit 2: the card's price, entitlements, buy, restore
    App/App.entitlements     Game Center
    App/PrivacyInfo.xcprivacy  App/Info.plist (GADApplicationIdentifier, SKAdNetworkItems)
```

- **CocoaPods, not Swift Package Manager** (Capacitor 8's default): the AdMob pod is one line in a
  text Podfile, as in funny, while an SPM package would be a hand edit of the Xcode project's
  package references. `Podfile.lock` only comes out of the macOS runner, so it is not committed.
- **A new Swift file needs four hand-written entries in `project.pbxproj`** (file reference,
  build file, group child, Sources phase); `shell.test.ts` fails when one is missing. funny put
  everything in `AppDelegate.swift` to avoid this; one file per concern reads better here.
- The app icon is `art/store/cover_square.png` (1024×1024, no alpha), the square cover's art
  without the logo; a tighter crop cut the ghosts in half. The launch screen is the game's background
  colour, no image.

- **Capacitor 8** (the version daydayup already depends on; funny's bridge pattern is the
  same API on 6 and 8). iOS 15 minimum (StoreKit 2; Apple warning 90068).
- `Host` gains `'ios'` (`server/src/protocol.ts` `HOSTS`): analytics, boards and problem
  reports can tell iOS apart on the dashboard.
- The backend base is the default absolute `https://hk.gamestao.com` (`net/backend.ts`
  `apiBase`); the server already answers CORS with `*`, so `capacitor://localhost` works.
- Swift only compiles on the CI's macOS runner (`.github/workflows/release-ios.yml`): every push to
  `main` that touches the shell builds it unsigned for the simulator, with no secrets; a tag
  `ios-v*` or a manual run archives, signs and uploads to TestFlight (`destination: none` stops at
  the IPA).

### The bridge contract (`window.HKNative`, injected at document start)

Every member is feature-detected so a newer JS bundle on an older shell degrades instead of
throwing; `v` is raised when the shell gains calls (2 with Game Center, 3 with AdMob, 4 with the
store). Answers are pushed, not settled by id: the shell calls `_gameCenter(state)`,
`_adState(state)` and `_store(state)` whenever a state changes and when the page posts
`gameCenter` / `adState` / `store` as it loads (a reloaded page asks again), `_adEvent(e)` as an ad
the page asked for comes and goes, and `_storeResult(r)` when a buy or a restore is over.

```ts
interface HKNative {
  // Game Center (step 2, built)
  gameCenter(): { alias: string | null; canSignIn: boolean } | null; // null until GameKit answers
  onGameCenter(cb: (s: { alias: string | null; canSignIn: boolean }) => void): void;
  gameCenterSignIn(): void; // presents Apple's kept sheet, only from a tap
  // ads (step 3, built)
  adState(): AdState | null; // null before the shell has sent one
  onAdState(cb: (s: AdState) => void): void;
  // AdState: { status: 'pending' | 'on' | 'off', rewarded: boolean, interstitial: boolean
  //            (loaded now), privacyOptions: boolean, error: string | null (last load failure) }
  onAdEvent(cb: (e: { kind: AdKind; event: 'started' | 'done'; ok: boolean }) => void): void;
  showAd(kind: 'rewarded' | 'interstitial'): void; // 'done' alone when it could not be shown
  adPrivacy(): void; // UMP's privacy options form, from settings
  // store (step 4, built)
  store(): StoreState | null; // null until StoreKit answers
  onStore(cb: (s: StoreState) => void): void;
  // StoreState: { products: { id, price (displayPrice) }[], owned: string[] (verified, unrevoked
  //               entitlements), canPay: boolean (false under Screen Time's purchase block) }
  onStoreResult(cb: (r: { op: 'buy' | 'restore'; outcome: string }) => void): void;
  // buy: 'owned' | 'cancelled' | 'pending' (Ask to Buy) | 'failed'; restore: 'owned' | 'none' | 'cancelled' | 'failed'
  buy(id: string): void; // Apple's purchase sheet, only from a tap
  restore(): void; // AppStore.sync(), then the entitlements again
  // shell (step 1, built)
  v: number;
  openUrl(url: string): void; // UIApplication.open, Safari; http(s) only
  saved: Record<string, string>; // the UserDefaults copy of the key store, as at launch
  save(key: string, value: string): void;
  languages: string[]; // Locale.preferredLanguages
  device: string; // 'iPhone15,2 iOS 18.1', for problem reports
}
```

## Shell

- **Portrait, iPhone only** (`TARGETED_DEVICE_FAMILY = 1`, `UIRequiresFullScreen`), status bar
  hidden, `ITSAppUsesNonExemptEncryption = false`.
- **System bars**: Capacitor's core SystemBars plugin shows the status bar at load unless its
  config says `hidden: true` (undoing `UIStatusBarHidden`), and it owns
  `prefersHomeIndicatorAutoHidden` through a non-open extension the bridge cannot override.
  So `capacitor.config.ts` sets `plugins.SystemBars.hidden`, which hides both.
- **Home gesture vs. the drag stick**: the bridge view controller defers system gestures on
  the bottom edge (`preferredScreenEdgesDeferringSystemGestures = .bottom`) and the home
  indicator stays hidden, or a drag near the bottom sends the game home.
- **Safe area**: `contentInset: 'never'` plus `viewport-fit=cover`, so
  `env(safe-area-inset-*)` reaches `WebPlatform.safeInsets()` (funny learnt `'always'` makes
  them read 0).
- **Audio**: `AVAudioSession` category `.ambient` (respects the silent switch, mixes with the
  player's music), and `navigator.audioSession.type = 'ambient'` where WebKit has it (iOS 17).
  Check on a phone that the music decks resume after a call and after an ad.
- **External links**: `window.open` from a Pixi tap is dropped silently in WKWebView
  (funny §10.3). `IosPlatform.openUrl` goes through the bridge to Safari. Never add our domains
  to `server.allowNavigation`.
- **Keyboard**: the problem-report text box (`platform/web/textAsk.ts`) can leave the page
  scrolled up after the keyboard closes, offsetting every tap (funny §10.6). Scroll back to 0
  on close and again after 400 ms; check that `bindStick` maps touches through the canvas'
  own `getBoundingClientRect()`.
- **Storage**: the save stays synchronous (`KeyValueStore`). The native side mirrors every key
  to `UserDefaults` and injects them at document start as `HKNative.saved`; writes go to both.
  Reads prefer localStorage and fall back to the native copy (`mirrorStore.ts`): after the web
  content process is killed and the page reloads, the injected copy is the launch's and older
  than localStorage, so only a wiped localStorage reaches it. Needs the `UserDefaults` reason
  (`CA92.1`) in `PrivacyInfo.xcprivacy`.
- **Languages**: WKWebView's `navigator.language` follows the app's declared localisations, so
  `Info.plist` lists the eleven the game ships (`CFBundleLocalizations`) and the bridge hands
  over `Locale.preferredLanguages` as well.
- **Debugging without a Mac**: TestFlight builds plus the in-game problem reports (they carry
  a replay). Debug builds set `webView.isInspectable = true` for the day a Mac is at hand.

## Game Center: the player's name

- At launch `GameCenter.swift` sets `GKLocalPlayer.local.authenticateHandler`. A player already
  signed in to Game Center in Settings is signed in silently (Apple shows its own "Welcome back"
  banner). When Apple hands back a sign-in view controller, the shell **keeps it and does not
  present it at launch**: no sheet over the first run. The settings panel then shows a
  **Game Center** button beside Back (`Portal.canSignIn` / `signIn`, from a tap). Not the
  lobby's name line, as first planned: the top bar has no room left between the name and the
  currencies, the panel none for a row of its own on a 16:9 iPhone SE, and the button is
  rarely there, since Game Center signs most players in by itself.
- The name is `GKLocalPlayer.local.alias` (the nickname the player chose; `displayName` can be
  a real name). `teamPlayerID` stays in the shell until the cloud save needs it.
- `IosPlatform.portal.userName()` returns the alias (`platform/ios/gameCenter.ts`); `accounts()`
  is **false**, so a player without Game Center goes by a dice name instead of being kept off
  the boards (`ui/playerName.ts`). An alias that fails `checkName` (length, characters, rude
  words) falls back to the dice name, as on CrazyGames. GameKit answers some time after launch
  and again after a sign-in; each new state redraws the lobby (`main.ios.ts`, as
  `main.crazygames.ts` does), and `PlayerName` sends the new name.
- Server: `rules.ts` takes a text `name` from `crazygames` and `ios` (`NAMING_HOSTS`). The
  server still trusts the client for the name, as it does on CrazyGames; verifying Game Center's
  identity signature comes with the cloud save, not before.
- Capability: Game Center on the App ID and in the profile (done), `com.apple.developer.game-center`
  in `App.entitlements` (`CODE_SIGN_ENTITLEMENTS`); enable Game Center on the App Store Connect
  version.

## Ads: AdMob

Built (step 3) in `App/AdMob.swift` and `platform/ios/admob.ts`.

- **Ids.** `GADApplicationIdentifier` in `Info.plist` is HolyKicker's own app id
  (`ca-app-pub-5437693117291100~7644915595`, the publisher funny uses too). Its two units
  (rewarded `…/1896010873`, interstitial `…/7607502555`) sit in `AdMob.swift` behind `live`, on
  since the listing (step 5, build 1.0 (13)); builds before it asked for Google's demo units,
  which serve test ads under any app id, while real units have no fill before the app is live
  (funny's first device test had none). Don't tap ads on your own phone in a live build. `Google-Mobile-Ads-SDK ~> 13.9` and
  `GoogleUserMessagingPlatform ~> 3.1` are pinned to the majors funny shipped; the
  `SKAdNetworkItems` list is funny's (Google's 50).
- **Consent.** Once the view is on screen (`viewDidAppear`, so the form has a presenter), UMP
  `requestConsentInfoUpdate` → `loadAndPresentIfRequired`; Google shows its form only in the
  EEA/UK, as configured under AdMob → Privacy & messaging. The SDK starts and loads only when
  `canRequestAds` (at once when an earlier launch already answered). Where
  `privacyOptionsRequirementStatus` is `required`, the settings panel's play-data row gains a
  third button, "Ad privacy", beside sharing and the policy (`Platform.adPrivacy`, `NO_AD_PRIVACY`
  elsewhere). Our own analytics consent card (`net/privacyChoice.ts`) stays: it is about our play
  data, UMP about Google's ads. Withdrawing consent there drops the loaded ads.
- **No ATT**, every request non-personalised (`npa=1`), as funny decided: no tracking prompt,
  "Data used to track you: none" on the privacy label. Revisit once there is fill data.
- **Mapping onto `Ads`.** The shell keeps one rewarded and one interstitial loaded, loading the
  next as one closes and retrying a failed load with a backoff (15 s doubling to 5 min).
  `rewardedAvailable` is true once a rewarded ad is loaded: it waits up to 20 s for the first
  (the lobby and the results lay themselves out again when it resolves), and is false at once
  when ads may not be requested. `rewarded` → true only when the reward was earned, resolved
  after the ad is closed; `midgame` → the interstitial if one is loaded, otherwise nothing (never
  waited for). `started` ← the ad's `adWillPresentFullScreenContent`, so the shell mutes the
  sound as on CrazyGames. An ad that has not started 10 s after the ask is given up. `banner` is
  `NO_BANNER` for now. Rewards are paid on the device, so no server-side reward check.
- **Why a load failed** ("GADErrorDomain 3: …", 3 is no fill) rides on the device line of a
  problem report (`IosPlatform.device`), since a TestFlight build has no readable console.

## The ad-free card (StoreKit 2)

Built (step 4) in `App/Store.swift`, `platform/ios/storeKit.ts`, `adFree.ts` and `ui/adFreeCard.ts`.

- Product: `com.gamestao.holykicker.adfree`, non-consumable, **US$3.99** (Apple's matching
  tier in every storefront), localised name in App Store Connect. The price shown in game is StoreKit's `displayPrice`, never a number in code.
- What it does, in `platform/ios/adFree.ts` (an `Ads` decorator, pure and tested):
  `rewardedAvailable` → true, `rewarded` → resolves true at once with no ad, `midgame` → no-op.
  The daily caps (3 ad chests, 2 quick patrols, …) stay as they are. `Ads` gains
  `adFree(): boolean` (false on every other host); the offer buttons drop their video badge
  (`showVideoBadges` in `ui/widgets.ts`, set by `main.ios.ts`).
- Ownership is StoreKit's, not ours: the shell reads `Transaction.currentEntitlements`
  (verified and not revoked) at every launch, and the page keeps the last answer (`hk.adFree` in
  the key store) so the first frame is right offline. `Transaction.updates`, listened to from
  launch, keeps it current (Ask to Buy approved later, a refund revokes it, a purchase on another
  device); each change redraws the lobby. A transaction is finished once the page has the new
  state; an unverified one grants nothing and is left alone. No server in the loop: the perk is
  local, StoreKit 2 verifies the signature on the device, and a jailbroken device that fakes it
  only skips its own ads.
- UI: a card under the chests in the Shop tab, iOS only: the price (StoreKit's `displayPrice`;
  "…" until it loads, and a tap then says the App Store cannot be reached) and **Restore** under
  it, then "Owned" once bought. Restore sits on the card rather than in settings, which has no
  room left on a 16:9 phone. `Platform.store` is `null` on every other host, so nothing is drawn
  there (CrazyGames forbids IAP; App Review 3.1.1 forbids pointing anywhere else to pay).
  `?store=fake` draws the card in the browser with a made-up price. The Shop tab is open from
  the first lobby on, so a reviewer finds the card without clearing a chapter.
- Analytics: a new `iap` event (`what`: buy or restore, `item`: adfree, `outcome`), and the `ad`
  event gets `free: true` when the card paid it; the dashboard's "watched an ad" leaves those out.
